# VolumeAttachment

## What and why

A VolumeAttachment records that a volume should be attached to, or detached from, one node. Some storage (a cloud block disk) must be attached to the machine before the node can mount it, and something has to track that step.

The **attach/detach controller** in kube-controller-manager creates one when a Pod that uses a volume from a CSI driver with `attachRequired: true` is scheduled to a node. The driver's **external-attacher** sidecar performs the attach and sets `status.attached`; the **kubelet** waits for that before it mounts. You normally never create one by hand; you read it to debug a Pod stuck in ContainerCreating.

## Minimal example

Tested on kind v0.33.0 with `kindest/node:v1.37.0` and kubectl v1.37.1 (2026-11-16). kind has no CSI driver, so the **attach/detach controller ran but no external-attacher did**: the object appears and stays unattached, which is the failure picture. A CSIDriver with `attachRequired: true` (see the CSI card), a static PV that uses that driver, a claim bound to it and a Pod on the worker:

```yaml
apiVersion: v1
kind: PersistentVolume
metadata: {name: pv-csi}
spec:
  capacity: {storage: 1Gi}
  accessModes: [ReadWriteOnce]
  persistentVolumeReclaimPolicy: Retain
  storageClassName: ""
  csi: {driver: fake.csi.example.com, volumeHandle: vol-0001}
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata: {name: csi-static}
spec:
  storageClassName: ""
  volumeName: pv-csi
  accessModes: [ReadWriteOnce]
  resources: {requests: {storage: 1Gi}}
---
apiVersion: v1
kind: Pod
metadata: {name: attach-demo}
spec:
  nodeSelector: {kubernetes.io/hostname: cnlab-worker}
  containers:
  - {name: c, image: alpine:3.21, command: [sleep, "3600"], volumeMounts: [{name: d, mountPath: /d}]}
  volumes: [{name: d, persistentVolumeClaim: {claimName: csi-static}}]
```

The controller creates the VolumeAttachment as soon as the Pod is scheduled; nothing sets `attached` to `true`:

```
$ kubectl get volumeattachment
NAME                                                                   ATTACHER               PV       NODE               ATTACHED   AGE
csi-295d1e6c9e1dd68fac7ee1d3fc244006b5dd08437df0540a0f245ad2c833cfb9   fake.csi.example.com   pv-csi   cnlab-worker       false      8m10s

$ kubectl get volumeattachment -o yaml     # trimmed
spec:
  attacher: fake.csi.example.com
  nodeName: cnlab-worker
  source: {persistentVolumeName: pv-csi}
status:
  attached: false

$ kubectl get pod attach-demo
NAME          READY   STATUS              RESTARTS   AGE
attach-demo   0/1     ContainerCreating   0          8m10s
```

## Key fields

Checked with `kubectl explain volumeattachment` on 1.37.

| Field | Meaning | Default |
| --- | --- | --- |
| `spec.attacher` | name of the CSI driver that must handle the request | required |
| `spec.nodeName` | the node the volume must be attached to | required |
| `spec.source.persistentVolumeName` | the PV to attach (or `inlineVolumeSpec` for inline volumes) | one source is required |
| `status.attached` | `true` once the external-attacher finished the attach | `false` until then |
| `status.attachError`, `status.detachError` | the last error, with `message` and `time` | unset |
| `status.attachmentMetadata` | information the driver returns for later steps | unset |
| name | `csi-` plus a hash of the volume, the driver and the node | generated by the controller |
| who writes | `spec` by the attach/detach controller; `status` by the external-attacher | n/a |

## kubectl

```bash
kubectl get volumeattachment                     # ATTACHER, PV, NODE, ATTACHED
kubectl get volumeattachment -o yaml             # spec, status.attached, attachError
kubectl describe pod attach-demo | sed -n '/^Events/,$p'   # FailedAttachVolume events
kubectl get csidriver                            # does this driver need an attach step?
kubectl delete pod attach-demo                   # the controller detaches after the Pod goes
```

## How it fails

| Symptom | Cause | Fix |
| --- | --- | --- |
| Pod stuck in `ContainerCreating`; event `Warning FailedAttachVolume attachdetach-controller AttachVolume.Attach failed for volume "pv-csi" : timed out waiting for external-attacher of fake.csi.example.com CSI driver to attach volume vol-0001` (first after about two minutes, then repeating) | The VolumeAttachment exists but no external-attacher for that driver sets `attached: true`; here no driver is installed | Install the driver (its controller Pods include the attacher); run kubectl get pods -A and look for its Pods |
| `ATTACHED false` for a long time | Same cause, or the driver returns an error: read `status.attachError` | `kubectl get volumeattachment -o yaml`; read the attacher and driver logs |
| The VolumeAttachment is still listed after the Pod was deleted (seen right after `kubectl delete pod`) | Detach is asynchronous and also needs the attacher to finish | Wait; if it never clears, the attacher is missing or failing, so fix it before deleting finalizers |
